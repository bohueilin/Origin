01 / The reference check

From an assumption
to something checkable.

A clear sequence for a complicated review. Try the five stages, then run the synthetic policy evaluation yourself.

What inputs were declared?

Bind Declared inputs are bound

Declared model, tool set, selected policy, and scenario battery are pinned into a single input digest. This binds the local policy evaluation; it does not prove that the named agent was inspected or run.

input · declared model + tools + policy + battery DIGEST BOUND

Which decisions were tested?

Challenge A deterministic battery runs

The same scenarios every time: actions that must be allowed, actions that must be denied, and actions that must escalate, meaning the policy should hand them to a person to approve; in this demo nothing is held and no one is asked.

battery · allow · deny · escalate DETERMINISTIC

Where did the policy disagree with the oracle?

Grade The oracle grades it

False accepts, false rejects, and catastrophic failures produce scored outcomes under the fixed oracle. Over-grants are counted on their own; matches elsewhere do not offset them.

oracle · FAR · FRR · over-grants EVALUATION RESULT

What does the artifact actually attest?

Attest Browser demo evidence is issued

The browser signs a synthetic Action/Run envelope over the local policy evaluation. It records not attempted: no named agent was contacted or executed, and no provider effect was confirmed.

envelope · bound to declared input · synthetic SIGNED

What can a reviewer re-check?

Reverify Offline UNTRUSTED; VOID if edited without re-signing

A reviewer re-verifies browser evidence offline and gets UNTRUSTED: its session signer is unpinned (no published key it must match) and it does not represent execution. An edit made without re-signing returns VOID; an edited copy re-signed with a new browser key still reads UNTRUSTED.

verify · intact browser evidence UNTRUSTED

verify · one field edited without re-signing VOID

What Origin is not.

Not yet validated by a customer

No design partner, no pilot, no paying user — today. Everything shown here is authored, synthetic, or machine-emitted from a scripted scenario; none of it is customer-owned. If a real workflow from a real reviewer is earned, it will appear on /proof, labelled as plainly as everything else.

Not production SaaS

A working prototype on synthetic sandbox evidence. Customer-specific execution requires separately agreed work.

Not a compliance certification

Origin's checks produce evidence for your reviewer; your gate decides. The public demo's evidence is session-signed (signed with a key your browser makes for that run) and unpinned (no published key it must match), so it is not Origin-issued. Nothing here certifies anything.

Not “safe” or “correct”

A green result means the check reproduces under this verifier: integrity and determinism, never “safe” or “correct”. That is the whole claim.

Not runtime enforcement

The runtime gate, controlled proxy and kill switch are proposed pilot architecture, not shipped.
