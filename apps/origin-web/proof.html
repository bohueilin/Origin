TR-A002 · available now

Machine-emitted trace of a scripted scenario, a real hash chain you can re-verify.

The events are scripted; the chain is computed. scripts/generate-tr-a002.mjs lists the same payments-ops scenario as twelve events (proposal, policy verdict, proxy hold, human approval, sandbox execution, a blocked over-scope retry) and commits each one to a SHA-256 hash chain. No agent, policy gate, proxy, approver or sandbox ran. The published file below is the script's exact output. The verify command re-derives the chain and fails if an event no longer matches its hash, or if final_digest or log_digest stops matching; a chain recomputed after an edit ends in a different final digest from the one published here. The file's top-level description (its type, emitter, label, scenario, agent, policy text, risk owner, proxy tool and hash spec) sits outside the chain and is not checked.

The 12 events, in order.

  1. Planproposal.createdScripted proposal: a $480.00 refund on order_8842.
  2. Planpolicy.evaluatedScripted policy step: $480 is over the $250 auto-cap and within the $500 ceiling. No rule engine ran.
  3. Heldverdict.require_approvalScripted verdict: require human approval. Risk owner: payments-on-call.
  4. Heldproxy.heldScripted hold: the event marks payments.refund as held and not dispatched.
  5. Heldapproval.requestedScripted request for approval from payments-on-call, with the verdict and side-effect scope.
  6. Approved (scripted)approval.grantedScripted approval: the event records payments-on-call granting the $480.00 refund. No person approved anything.
  7. Executed (scripted)proxy.executed_sandboxScripted execution: the event marks the refund as executed in a sandbox. No sandbox call was made and no money moved.
  8. Recorded (scripted)action.recordedThe script records approver, verdict and scope in this event.
  9. Planretry.proposed_over_scopeScripted retry: a second refund of $920.00, above the $500 ceiling.
  10. Blockedverdict.deny_or_blockScripted verdict: deny. $920 exceeds the approved scope.
  11. Blockedproxy.blockedScripted block: the event marks the over-scope refund as blocked and never dispatched.
  12. Sealedevidence.digest_sealedHash chain over the preceding 11 events is committed to the final digest.

Event 11 is the one to inspect: the scripted agent exceeds its scope and the scripted proxy blocks it. The block is an event in the chain: editing it breaks verification or changes the final digest.

Verify this artifact yourself

No install needed, paste the downloaded JSON into /verify and it re-checks offline in your browser (green = the chain re-derives; an event edited without recomputing the hashes returns VOID; the file's top-level description, its type, label, policy text and other descriptive fields, is outside the chain). Or clone the public repo github.com/bohueilin/Origin and run:

# in the repo — re-derive the hash chain of the published JSON
npm run proof:verify
# → PASS every event hash + prev_hash link verifies · digest recomputes

# or verify the *published* artifact directly:
curl -sO https://originphysicalai.com/proof/tr-a002.json
node scripts/verify-tr-a002.mjs tr-a002.json
# → PASS. Now edit one amount / actor / verdict and re-run → FAIL

The verifier recomputes every event hash from its own bytes and checks the links. Edit any field of any event without recomputing the hashes and it exits non-zero; recompute them and the final digest no longer matches the one published on this page. That is what "tamper-evident" means here. This demonstrates tamper-evident trace plumbing on a scripted scenario, not production security. The in-page re-check runs the same verifyChain that /verify uses; it demonstrates tamper evidence on a scripted trace, not production security.

In plain English: the published JSON commits each event to the next one, and the final digest commits all twelve events. Change any value in any event and re-verification fails, unless every later hash is recomputed; then the final digest no longer matches the one published on this page. Whitespace and the file's top-level description are not covered.

TR-A001 · available now

Authored evidence specimen, the format of a package.

Authored specimen · illustrative, not a machine-emitted run. The fields below show the exact shape of an Origin evidence package; the scenario, timestamps, and hash are authored to that schema, not recorded from a live agent.

A single high-consequence action, a payments-ops agent proposing a refund above its auto-cap, worked through the proposed runtime design (not built): the policy verdict, the controlled tool-call proxy, the human approval, a blocked over-scope action, and the audit-chain digest. TR-A002 above writes the same scripted scenario as a computed hash chain: same scenario, computed hashes.

Agent workflow
payments-ops-agent, an internal-ops agent authorized to issue customer refunds, within scope and budget.
Proposed action
Refund $480.00 for order_8842 via tool payments.refund.
Policy in force
Tool in allowlist · auto-cap $250 · above-cap refunds require a human approval.
Policy verdict
require-approval, $480.00 is over the $250 auto-cap, so the action is held rather than auto-executed.
Risk owner
payments on-call, the named human who owns the decision on above-cap refunds.
Tool-call proxy event
payments.refund is held at the proxy until approval, the agent has no path to the side effect except through the controlled proxy, so nothing moves while the verdict is require-approval.
Human approval
payments on-call approves the held refund. The proxy then executes exactly the approved action ($480.00 → order_8842) and the approval is recorded with who, when, and scope.
Blocked over-scope action
A second refund attempt above the approved scope is blocked at the proxy and recorded, the earlier approval covered one action only; it does not widen the agent's standing authority.
Audit-chain digest
Every entry, proposal, verdict, proxy hold, approval, execution, and the blocked over-scope call, is written into a hash-chained, tamper-evident record that can be replayed and exported as the evidence package.
